1. VISIÓN GENERAL DEL BOT
================================================================================

CONCEPTO:
---------
El bot será un cliente IRC que se conecta al servidor ft_irc como un usuario
normal, pero con la capacidad de:
  • Responder automáticamente a ciertos comandos
  • Monitorizar canales
  • Realizar acciones específicas
  • Interactuar con otros usuarios

CARACTERÍSTICAS PRINCIPALES:
  ✓ Conectarse al servidor con autenticación
  ✓ Unirse a canales específicos
  ✓ Responder a comandos prefijados (ej: !help, !echo, !info)
  ✓ Realizar acciones moderadoras (futuros)
  ✓ Mantener conversaciones automáticas
  ✓ Funciones de utilidad (hora, contador, etc)

NICK DEL BOT:
  • Por defecto: "ft_bot"
  • Configurable por parámetro

CANALES POR DEFECTO:
  • Se unirá automáticamente a los que especifiques
  • Ej: #general, #random, #help

2. ARQUITECTURA Y ESTRUCTURA
================================================================================

DISEÑO MODULAR:
---------------
Bot.cpp/Bot.hpp (Nueva clase Bot)
    │
    ├─ Conecta como cliente IRC
    ├─ Hereda características de Cliente IRC
    ├─ Maneja eventos de canal
    └─ Procesa comandos específicos


DIFERENCIAS CON CLIENTE NORMAL:
  • Bot es también un "cliente" del servidor
  • Se conecta directamente (no espera conexión entrante)
  • Se autentica automáticamente
  • Posee un parser de comandos especial
  • Ejecuta acciones programadas


RELACIÓN CON COMPONENTES EXISTENTES:
  • Server: Lo gestiona como un cliente normal (sin cambios)
  • Client: El Bot actuará como cliente desde el lado del servidor
  • Channel: Interactúa normalmente con canales

PATRÓN DE DISEÑO:
  • Bot puede heredar de Client (si es necesario)
  • O ser una clase independiente que se conecta como cliente TCP
  • RECOMENDADO: Clase Bot independiente que maneja socket TCP directamente

FLUJO DE CONEXIÓN DEL BOT:
  main() ejecuta
    ├─ Inicia Server
    ├─ En paralelo o secuencial, inicia Bot
    │   ├─ Bot crea socket TCP
    │   ├─ Se conecta a localhost:puerto
    │   ├─ Envía PASS contraseña
    │   ├─ Envía NICK ft_bot
    │   ├─ Envía USER
    │   ├─ Se une a canales
    │   └─ Loop de lectura de mensajes
    │
    └─ Server continúa aceptando clientes

CONSIDERACIÓN IMPORTANTE:
  El Bot se ejecutará EN EL MISMO PROCESO que el servidor
  Opciones:
    A) Threads: Complejo para 42, no recomendado
    B) Fork: Crear proceso hijo (posible pero complicado)
    C) RECOMENDADO: Bot dentro del mismo proceso, manejo secuencial
       El Bot procesa su conexión en el loop principal del servidor

```cpp
// main.cpp MEJORADO
int main(int argc, char* argv[])
{
    if (argc < 3) {
        std::cerr << "Usage: ./ircserv <port> <password>" << std::endl;
        return 1;
    }
    
    int port = std::atoi(argv[1]);
    if (port <= 0 || port > 65535) {
        std::cerr << "Error: invalid port" << std::endl;
        return 1;
    }
    
    std::string password = argv[2];
    if (password.empty()) {
        std::cerr << "Error: password cannot be empty" << std::endl;
        return 1;
    }
    
    try {
        Server server(port, password);
        
        // Iniciar bot en fork (proceso separado)
        pid_t pid = fork();
        if (pid == 0) {
            // Proceso hijo: ejecuta el bot
            sleep(1); // Esperar a que el servidor esté listo
            Bot bot("localhost", port, password);
            bot.run();
            exit(0);
        }
        else if (pid > 0) {
            // Proceso padre: ejecuta el servidor
            server.run();
        }
        else {
            throw std::runtime_error("fork() failed");
        }
    }
    catch (const std::exception& e) {
        std::cerr << "Error: " << e.what() << std::endl;
        return 1;
    }
    
    return 0;
}
```

FLUJO COMPLETO DE EJECUCIÓN:
-----------------------------

1. main() inicia Server
2. main() hace fork() para Bot
3. Proceso hijo (Bot):
   a) Bot.__init__()
      - Crea socket TCP
      - Se conecta a localhost:puerto
      - Se autentica (PASS, NICK, USER)
      - Se une a #general y #random
   b) Bot.run()
      - Loop infinito leyendo mensajes del servidor
      - Cada PRIVMSG con "!" se procesa
      - Ejecuta comando correspondiente
      - Envía respuesta PRIVMSG al canal
4. Proceso padre (Server):
   - Continúa aceptando clientes normales
   - El bot actúa como cliente regular
   - No hay diferencia en cómo se maneja

  ✗ Viola separación de responsabilidades
  ✗ Más difícil de testear


OPCIÓN 3: BOT EN THREAD (NO RECOMENDADO PARA 42)
--------------------------------------------------
Ventajas:
  ✓ Compartir memoria facilita comunicación

Desventajas:
  ✗ Threads pueden estar restringidos en 42
  ✗ Sincronización complicada
  ✗ Race conditions posibles


RECOMENDACIÓN FINAL: OPCIÓN 1
------------------------------
Implementar Bot como cliente TCP separado en fork():
  • Es la solución más limpia
  • Simula un cliente real IRC
  • Demuestra comprensión de arquitectura
  • Fácil de extender
